# Performance data is fetched separately, cached for 2 hours, and never blocks balance data

Client details and the v3/v4 performance endpoints are fetched by `PerformanceFetcher` (`performance.py`), not by the coordinator. They are cached for `PERFORMANCE_UPDATE_INTERVAL` (2 h) and their failures never raise, so balance data keeps updating when they fail. Only a *complete* fetch (client details, v3 and v4 all succeeded) refreshes the cache timestamp; a partial or failed fetch keeps the last good value for every field it could not fetch and leaves the timestamp alone so it is retried, but not before `PERFORMANCE_RETRY_INTERVAL` (15 min) has passed since the failed attempt (#37). Without that backoff a permanently failing endpoint (e.g. no access to a v4 endpoint) would re-issue 3+ calls on every 5-minute poll, against the rate-limit goal of ADR-0004. Until a field has been fetched successfully it is `None` and the sensor is `unknown`, never `0.0`: performance sensors use `SensorStateClass.MEASUREMENT`, so a placeholder zero would be recorded as a real long-term statistic (#15).

# Sensors stay available through transient API failures

A single failed update does not mark a sensor unavailable. Sensors keep their last value and only go unavailable after `max(15 min, 3 × update_interval)` of consecutive failures (`AVAILABILITY_FAILURE_FLOOR`, `AVAILABILITY_FAILURE_INTERVAL_MULTIPLIER` and `AVAILABILITY_FALLBACK_UPDATE_INTERVAL` in `const.py`, applied in `sensor.py`). The Saxo API and the token refresh both fail briefly from time to time, and flipping balance sensors to `unavailable` on every blip would break automations and leave gaps in recorded history. The cost is that a short outage shows stale values rather than an explicit error. Because the update interval changes with market hours (see [ADR-0004](0004-market-hours-aware-polling-and-rate-limiting.md)), the threshold scales with it instead of being a fixed number of minutes.
